## Design Specificity Verdict

**LLM assessment: a competent shadcn template wearing a Voni costume.** Engineering coherence is real — every route shares the shell (H1 + subtitle + Card/Table + skeleton + error boundary), and the durable-job system (JobPill, header counts, `/jobs` triage) is coherent everywhere. But Dashboard, Agents, Campaigns, Leads, Calls, Numbers, Jobs are structurally interchangeable: header block, then cards or an 8/7/4-column table. Nothing in the layout says "voice employee," "phone calls," or "conversion." The dashboard shows nine undifferentiated pipeline-stage cards rendering "—" plus "No activity yet" — it tells an operator Voni does nothing, while the product promise is conversion. Voice, the product's medium, is buried in wizard step 2. The two genuinely authored-feeling pieces are the ambient job system and the copilot confirm gate; everything else is category-interchangeable admin.

**Deterministic scan:** static `detect --json` reported **0 findings on both `voni/src/app` and `voni/src/components`** (exit 0; no project ignores exist to suppress anything). The runtime overlay on 5 live pages found 13/7/8/10/7 flags — but the bulk traces to shared chrome, not page code (see false positives). Genuinely new catches vs. the LLM review: over-long lines (~89–155 chars on campaigns/jobs/wizard), one cramped-padding inline link, and an em-dash count that doesn't reconcile with source (10 claimed vs. 2 rendered).

**Visual overlays:** no persistent overlay was left for a human tab — the overlay ran in throwaway automation tabs during evidence collection and was cleaned up with the live server. No injections remain in any user-visible page.

## Overall Impression

The backbone is excellent (durable jobs as ambient UI, calibrated delete friction, preconditions stated before the click) and the skin is competent-but-generic. The single biggest opportunity: make the core loop — agents → calls → campaigns → customers — visible. Today the dashboard funnels to nothing, call detail and lead timeline are promise-shaped holes, and the two differentiators (voice, durable work) are either buried or already the best part. Fix the loop's visibility and the app starts feeling like Voni instead of a well-built template.

## What's Working

1. **Durable work as ambient UI, not modal anxiety.** JobPill (work-in-flight only, auto-clearing, expandable, height-published via `--job-pill-h` so it never covers the wizard Save), header jobs button with live counts, `/jobs` triage with Active/Needs-review/All + search + per-row Cancel/Retry/Dismiss. Survives reload/navigation. Few small-team tools do this coherently.
2. **Delete-agent friction calibrated, not copy-pasted.** Typed-name gate + `neverProvisioned` short copy + enumerated consequences (AssemblyAI removal, number unbind, job-history erase, call records kept) + error stays in-dialog. Intent is stated in code and delivered in UI.
3. **Preconditions stated before the click.** Campaign detail computes `activationBlocker` server-side; draft agents flagged in four places; dialer distinguishes "outside calling window" from "broken." Error prevention as product voice.

## Priority Issues

- **[P1] Dashboard contradicts the product's essence.** Nine "—" stage cards plus "No activity yet" while the promise is conversion. *Why:* first screen tells operators the product does nothing; no path from data to action. *Fix:* 4 outcome cards (Leads worked / Connected / Qualified + Appointments / Needs human handoff), each linking to its filtered list, plus one "Next action" strip; keep the funnel collapsed secondary. *Suggested command:* `$impeccable layout`
- **[P1] Call detail and lead timeline are promise-shaped holes in the core loop.** Twin "not implemented / will appear here" cards for transcript, reasoning trace, timeline — the three things justifying voice agents over a dialer. *Why:* scaffolding shipped as UI erodes trust at the exact moment of curiosity. *Fix:* remove the placeholder cards; show what exists (parties, timestamps, duration, consent, pipeline state, linked campaign/jobs) with onward links. *Suggested command:* `$impeccable distill`
- **[P1] Icon-only desktop rail + ghost "Voice" button undersell the differentiators.** `SidebarProvider open={false}` hides all labels behind tooltips; the copilot entry is a ghost button collapsing to "…". *Why:* first-timers can't scan; the flagship feature (voice copilot operates the product) is nearly invisible. *Fix:* default rail expanded on lg+, keep icon-only smaller; promote copilot to a labeled "Voice copilot" button with a hint on `/agents/new` pointing at its header location. *Suggested command:* `$impeccable layout`
- **[P2] Leads table shows everything, explains nothing; import path is a riddle.** 8 columns force horizontal scroll on the finding that matters (who needs calling next); "Import CSV" jumps to `/campaigns` with no continuity. *Why:* the money action (who to call next) drowns in columns. *Fix:* collapse Intent/Blocker/Next-action into one "State" cell (next action primary, rest tooltip); freeze Name/Stage/Next; rename import "Import via a campaign" and land on the campaign picker. *Suggested command:* `$impeccable layout`
- **[P2] Generation mental model leaks onto the user.** Placeholder rows, `?job=` pointers, consumed-job Back-stripping, "form below still shows the placeholder" — handled correctly in code, visible to the user. *Why:* users must hold the draft/placeholder/saved distinction in working memory. *Fix:* name it once in UI ("Draft — generating" already works), never expose raw job ids in copy; add a 3-line summary header on review (name · voice · language · goals/tasks counts) so "save as shown" is verifiable without reading the whole form. *Suggested command:* `$impeccable clarify`

**Sam (Keyboard/a11y) — dashboard + wizard:** positives — `aria-current="step"`, focused step headings, `aria-disabled` pagination, `aria-live` job rows. Failures: icon-only rail kills scanning for keyboard/AT users; `TagField` focus jumps yank focus on validation; copilot call controls are small, packed icon targets; fixed JobPill (z-40) and copilot panel (z-50) overlay content with no skip/dock.

**Alex (Power User) — dashboard → campaign:** no date range, campaign/agent filter, or configurability on the dashboard; jobs search matches only title/kind/status with a 50-row cap; campaign queue has no search/sort; leads have no bulk stage/consent change; zero keyboard shortcuts. The core loop (find stalled leads → retry → re-queue) requires opening rows one by one.
