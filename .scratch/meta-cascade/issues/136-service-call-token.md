# 136 — short-TTL HMAC token binds call + subject

**Status: done.** Branch `cluster/deploy-136-139`, commit `57ad0584`, base `33e85a57`.

- **Built:** `cascade/token.py` gains `mint_call_token` / `verify_call_token` / `CallTokenRegistry`. The token is `ct1.<b64url(stable_json claims)>.<hmac sha256 hex>` — ticket 64's one construction (canonical JSON + HMAC under the envelope secret), domain-separated by a `kind: "call-token"` claim. Claims: call id, subject, issued/expires, nonce. TTL is `envelope.ttl_ms` (60 s, ticket 04), never a literal.
- **Verified before anything:** `transport.handle_browser_call` verifies signature + expiry, then the call/subject bindings against the signed body, then claims once — all before `adapt_body`, `backend_factory` or a vendor socket. Errors: `CallTokenExpired`, `CallTokenCallMismatch`, `CallTokenSubjectMismatch`, `CallTokenSignatureMismatch`, `MalformedCallToken`, `CallTokenReplayed`, `CallAlreadyConnected`; none echoes the token. Release on socket end; a reconnect mints a new token.
- **App side:** `voni/src/lib/voice/cascade-token.ts` (`signCallToken`, required `ttlMs`) with `cascade/call_token_vectors.json` generated by Node's crypto, so the two signers cannot drift.
- **Proof:** `cascade.test_call_token` 20, `test_transport` +7 (`CallTokenAtConnectTests`), `test_server` +1; TS `cascade-token.test.ts` 4. Each was red before implementation (missing imports / attribute).
